### 案件类型覆盖（分层策略）

| 类型 | 支持等级 | 行为 |
|---|---|---|
| 行政处罚信息 | L1 完整支持 | 自动判定可申请日与前置条件 |
| 经营异常名录 | L1 完整支持 | 无等待期，直接判定 |
| 严重失信主体名单 | L2 指引支持 | 给材料清单与官方入口，**不给结论** |
| 重大税收违法失信 | L2 指引支持 | 同上 |
| 海关失信企业 | L2 指引支持 | 同上 |
| 法院失信被执行人 | L3 仅导航 | 只给官方查询入口（不属行政修复路径） |

这个分层是刻意的：**宁可说"这类我们判断不了"，也不给一个错的可申请日。**

## 八、风险提示

| 风险 | 现状 | 建议 |
|---|---|---|
| 数据库含真实企业材料 | 无强制手段 | 演示只用虚构数据，演示完 `DROP DATABASE` 重建 |
| 本机磁盘未加密 | MySQL 5.7 无静态加密 | 开 BitLocker，笔记本丢失即整库泄露 |
| MySQL 版本偏低 | 5.7.26，文档要求 8.x | 现用语法兼容；若引入窗口函数或 `utf8mb4_0900_ai_ci` 会报错，届时升级 8.4 前先备份 `Data` 目录 |
| 密钥明文 | `.env` 中 `XFT_SIGN_KEY` | 仅限本地；上公网前改为环境变量注入 |
| 全站 HTTP | 未启用 TLS | 手机扫码链路风险最高，试用前必须解决 |
