## 1. 产品定位

面向**民营企业**的信用修复自助平台：把「我该不该修、能不能修、写什么材料、交到哪、交完有没有生效」这条原本只能靠中介或熟人打听的链路，变成企业自己可以走完的流程。

### 1.1 产品边界（写进章程，不可越界）

| 编号 | 边界 | 说明 |
| --- | --- | --- |
| B-1 | 不代办 | 不代替企业提交申请，只准备材料与指引 |
| B-2 | 不承诺结果 | 不承诺「包过」「必删」，只输出条件核验与材料质量 |
| B-3 | 不替代行政机关 | 平台出具的是**状态凭证**，不是行政决定书 |
| B-4 | 不做内部渠道 | 明确反对「有关系能加急」的中介话术 |
| B-5 | 数据最小化 | 只收集办理必需字段，不留身份证号、银行流水 |

### 1.2 要解决的问题

1. **不知道能不能修**：失信类型、公示期、最短修复期限分散在十余部法规里。
2. **不知道写什么**：申请书、承诺书、整改说明格式各地不一，企业反复退件。
3. **不知道进度**：材料交上去后无下文，多部门流转无感知。
4. **修了没生效**：官方已修复，第三方平台（企查查、天眼查）仍显示失信。
5. **举证成本高**：向银行、招标方证明「已修复」只能拿截图，无法核验真伪。
6. **易被中介骗**：市场存在收费「删除失信记录」的诈骗。

## 3. 主流程

```
① 注册/登录 → ② 录入企业信息 → ③ 智能诊断（等级·可申请日·材料清单·法律依据）
   → ④ 材料工坊（模板生成 → 编辑 → AI 润色 → 跨文书一致性校验 → 导出 PDF/Word）
   → ⑤ 办理进度（提交、受理、审核、决定，任务拆解与提醒）
   → ⑥ 同步监测（多源渠道巡检，识别"官方已修复但第三方未更新"）
   → ⑦ 异议中心（一键生成法律异议函，可下载寄送）
   → ⑧ 数字凭证（哈希链存证 + 签名 + 二维码） → 银行/招标方扫码核验
```

分支：
- ③ 判定「未届满」→ 输出倒计时与到期提醒，不允许生成正式申请书。
- ④ 校验不通过 → 阻断导出，标红具体字段。
- ⑥ 无差异 → 直接进入凭证签发。
- ⑦ 异议后 3 个工作日未更新 → 升级为「监管投诉建议」。

## 5. 业务规则

### 5.1 失信分级与最短公示期

| 等级 | 情形 | 最短公示期 |
| --- | --- | --- |
| 轻微 | 一般行政处罚、经营异常（已补报） | 3 个月 |
| 一般 | 较重行政处罚 | 6 个月 |
| 严重 | 严重违法失信名单 | 12 个月 |
| 特别严重 | 特定领域（食品药品、安全生产等） | 36 个月 |

> 上述期限为**演示默认值**，存于 `rule_params` 表，运营后台可改；正式使用前须由法律专业人员依据现行法规逐条校准。

### 5.2 可申请修复日

```
经营异常名录类（补报年报、更正公示信息）：
    applyFrom = removed_date          // 移出即视为义务履行完毕
行政处罚类：
    applyFrom = listed_date + minMonths(level)
```

### 5.3 三项法定条件核验

| 条件 | 判定依据 |
| --- | --- |
| 已履行相关义务 | `removed_date` 非空 或 处罚已缴款 |
| 整改措施已落实 | 已生成《整改情况说明》与《守信承诺书》 |
| 无新增同类失信 | 近 12 个月同类型案件数为 0 |

三项全满足 → 可申请；任一不满足 → 输出阻塞原因与倒计时。

### 5.4 材料矩阵

| 等级 | 材料 |
| --- | --- |
| 轻微 / 一般 | 申请书、承诺书、整改说明、授权委托书、材料目录 |
| 严重 | 上述 + 整改计划书 + 第三方证明 |

### 5.5 文书槽位三分类

| 类型 | 含义 | 谁可改 |
| --- | --- | --- |
| LOCK | 企业名称、信用代码、决定文号、日期等事实 | 系统锁定，AI 与用户都不可改 |
| GEN | 说明性段落（整改情况、承诺内容） | AI 可改写，用户可编辑 |
| DER | 派生值（份数、日期落款） | 系统计算 |

AI 输出必须**原样包含全部 LOCK 槽位文本**，否则判定失败、回退模板——这是防止「AI 编造文号」的硬闸门。

### 5.6 凭证算法

```
digest    = SHA256(code|name|caseId|docNo|event|authority|issuedDate)
prevHash  = 上一条凭证的 digest（首条为 64 个 0）
signature = HMAC-SHA256(digest + prevHash, XFT_SIGN_KEY)
```

核验时按当前库内数据重算 digest 并比对：一致 → 有效；不一致 → 被篡改；`revoked_at` 非空 → 已撤销；超过 `valid_until` → 已过期。

### 5.7 案件状态机

```
draft → diagnosed → materials_ready → submitted → reviewing → repaired
                                                       ↘ rejected → (补正) → materials_ready
```

| 分组 | 表 | 说明 |
| --- | --- | --- |
| 身份 | `users` `sessions` `orgs` `org_members` `enterprise_members` | 账号、会话、机构与成员关系 |

## 12. 合规与风险

| 风险 | 应对 |
| --- | --- |
| 被认定为「代办中介」 | 五条边界写进用户协议与首屏提示 |
| AI 编造文号/日期 | LOCK 槽位强制校验，失败回退模板 |
| 数据来源合法性 | 仅采集公开发布信息，遵守 robots 与频率限制 |
| 凭证被质疑效力 | 明确「证明数据一致」，不宣称行政效力 |
| 法规变动 | 参数表化 + 版本号 + 变更留痕 |
