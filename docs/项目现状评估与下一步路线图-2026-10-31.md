# 信复通项目现状评估与下一步路线图

- 日期：2026-10-31（北京时间）
- 项目：`/home/simon/项目/信复通/app`
- 基准需求：`docs/需求文档.md`（v2.0）；同时参考项目根目录 `docs/需求文档-PRD-v1.0.md`。
- 范围：需求与源码对照、运行健康检查、前端构建、关键服务隔离复核。本轮未修改业务源码、未写业务数据库、未调用 AI、未部署。
- 本文是阶段路线图，不是逐行编码实施计划；后续按每个工作包单独细化实现和测试。

## 1. 结论

现有 Vue 3 / Node.js / MySQL 分层架构可以继续使用。平台已经形成可展示的主流程骨架，但尚不能把“M1 已交付”理解为“新企业可独立办理且关键约束均已验收”。

下一阶段建议命名为 **M1.1：补齐办理闭环与可信校验**。先处理权限、新用户入口、诊断、材料与凭证约束，再进入 M2 的真实数据与运营能力建设。

| 文书服务隔离复核 | 两份文书的 LOCK 分别为“正确企业”“错误企业”，仍返回 100 分、0 问题 | 复现跨文书一致性校验缺口 |
| 注册服务隔离复核 | 传入 `role=admin` 后，待写入用户角色为 `admin` | 复现角色输入信任问题；未向实际数据库注册账号 |
| 凭证服务隔离复核 | 对草稿案件连续调用两次签发，均进入凭证插入路径 | 无状态拦截及重复返回路径；实际唯一键冲突行为未在业务库测试 |
| 路由与 SQL 静态核对 | 建企业、建案件仅出现在种子脚本；业务代码没有案件阶段迁移入口 | 新用户闭环和状态机尚缺 |
| 测试入口核对 | 两份 package.json 无测试命令，项目自有源码范围未发现测试文件 | 需要为关键业务约束补回归验证 |

隔离复核方式：在单独 Node 进程内将 `src/db.js` 的 `all/one/run` 替换为内存桩，再调用现有 service；所有写入均仅保留在内存。它验证服务逻辑，不替代数据库集成和浏览器端到端测试。

## 3. 需求与实现的主要差距

| 优先级 | 项目 | 当前实现证据 | 下一步验收要求 |
| --- | --- | --- | --- |
| P0 | 注册权限 | `src/routes/auth.js` 将请求体直接交给注册服务；`src/services/auth.js:14` 接受 `admin/org` | 公开注册固定普通企业角色；管理员和机构角色经受控流程分配 |
| P0 | 机构隔离 | `src/services/auth.js:61` 返回全部企业；`canAccess` 只检查机构成员身份，不检查目标企业授权 | 建机构—企业授权关系；撤销后列表、详情、文书、任务、签发入口均拒绝访问 |
| P0 | 成员操作权限 | `requireEnterprise` 对应的 guard 实际只检查能否访问企业，未按 owner/member 区分动作 | 将可见范围与可执行动作分别校验，成员不能获得负责人全部写权限 |
| P0 | 企业建档/案件创建 | 注册仅创建用户；`Dashboard.vue` 只能进入已有案件；缺少企业和案件创建 API | 空账号可建企业、建案件并进入诊断，刷新重登后仍保留 |
| P0 | 诊断真实性 | `src/services/rules.js:68` 把整改、无新增同类失信固定为真；处罚类型直接视为已履行义务；eligible 仅看日期 | 条件有事实/证据来源；缺资料返回“待确认”；全部必需条件满足才可申请 |
| P0 | 材料事实约束 | `src/services/docs.js:92` 只统计非空 LOCK 文本，未按字段比较；save 接受整段 HTML | 字段有标识，与案件事实及跨文书取值对照；手改、AI、恢复、导出使用同一套约束 |
| P0 | 导出拦截 | `src/routes/sync.js:118` 不检查资格或文书校验结果，直接生成 PDF | 未届满不能导出正式申请；校验不通过时直接请求 API 也不能绕过；允许的预览草稿须明确标识 |
| P0 | 办理状态机 | 任务完成仅更新 tasks.status；cases.stage 没有迁移入口 | 按合法迁移表更新案件、任务和时间线；退回补正可重走流程，非法跳转被拒绝 |
| P0 | 凭证签发与幂等 | `src/services/cert.js:17` 不判断修复依据，直接 INSERT；无重复签发返回逻辑 | 先定义凭证证明对象及签发条件；相同依据重复签发返回同一结果，含并发测试 |
| P0 | 凭证范围与内容 | 代码注释称案件内链，实际查询全局上一张凭证；有效期等未全部纳入签名；PDF 固定宣称“已依法完成信用修复” | 明确链范围；签名覆盖必要元数据和证据快照；篡改有效期也须失败；文案与证据一致 |
| P1 | 手工编辑与历史版本 | 前端只有 v-html 预览、AI、恢复、PDF；后端保存覆盖同一行并递增版本号 | 增加 GEN 段落编辑；版本快照可查看/恢复，不能只保留数字 |
| P1 | 严重等级材料 | 规则要求 plan，但现有种子仅五类模板；第三方证明缺少独立材料项 | 材料清单、模板及证明附件一致；明确首版支持的类型和等级 |
| P1 | 异议办理 | createObjection 只写数据库为 sent，无发送集成；缺下载入口和超期升级 | 区分“已生成/用户已寄送/已收到回复”；记录用户实际办理，不把落库等同发出 |
| P1 | 真数据接入 | checks.js 使用内置 observe() 模拟，不存在独立真实 provider | 先做人工核验/授权导入与证据记录，再接具备使用条件的数据源 |
| P1 | 交付一致性 | 老部署套件在 platform；运行说明引用的 app/docs/部署手册.md 不存在；PDF 子进程写死 python3 | 给 app 补部署说明与运行配置；统一 Python 可执行文件配置并实测 Windows 路径 |
| P2 | 订阅/融资/提醒/小程序 | 表或演示基础存在，业务未闭合 | 在基础流程与使用反馈稳定后分模块建设 |

其他文档漂移：schema.sql 实际有 **26 张建表语句**，需求与 README 写 24；默认会话时长代码为 7 天，需求写 30 天；凭证摘要/签名公式也与需求不同。需明确选择后统一文档与实现，不宜继续按现有勾选状态宣传完成度。

## 4. 建议的实施顺序

### 工作包 A：权限与数据边界

**主要文件**：`src/services/auth.js`、`src/routes/auth.js`、各业务路由、`db/schema.sql`、新增版本化迁移文件。

- [ ] 固定公开注册角色；增加受控的角色分配规则。
- [ ] 明确企业 owner/member 和机构账号的动作权限矩阵。
- [ ] 建立机构—企业授权、撤销和审计关系，去掉演示全量放行逻辑。
- [ ] 在所有按案件/任务/凭证读取和写入的入口复用校验，不能只在前端隐藏按钮。
- [ ] 补关键回归：注册传 admin 不能提权；企业 A 不能读取 B；无授权机构不能看 B；撤销授权立即生效；只读成员不能签发。

**交付条件**：上述负向用例均通过，且正常授权访问仍可用。

### 工作包 B：从空账号开始办理

**主要文件**：`src/routes/workspace.js`、新增企业/案件业务服务、`web/src/api.js`、`web/src/views/Dashboard.vue`、企业建档和案件录入组件、数据库迁移。

- [ ] 企业建档及信用代码校验；案件录入类型、日期、机关、文号、义务履行与整改事实。
- [ ] 新建企业时用事务创建负责人关系，明确已有企业的加入/认领规则。
- [ ] 新账号工作台提供“创建企业”，已有企业提供“新建案件”，补表单错误和空态。
- [ ] 创建案件后初始化必要任务、渠道和时间线。
- [ ] 跑通“注册→建档→建案件→诊断→重登查看”的端到端测试。

**交付条件**：新用户不需要开发者改库或灌种子就能开始办理；可按 v1 PRD 的三分钟目标验收。

### 工作包 C：诊断与状态机

**主要文件**：`src/services/rules.js`、`src/services/diagnose.js`、`src/routes/workspace.js`、`web/src/views/CaseDetail.vue`、任务/证据相关数据模型。

- [ ] 先支持明确的一类完整案例，再扩展类型；分级依据、地区、来源、版本和生效时间可追溯。
- [ ] 将“事实未知”“条件不满足”“条件满足”分开；日期届满与其他必需条件共同决定资格。
- [ ] 无移出日期时显示具体缺失事项，不输出“预计 null 后可申请”。
- [ ] 由服务统一处理案件迁移，迁移、任务和时间线在事务内保持一致。
- [ ] 验证正常办理、未届满、未缴款、未整改、有同类新增、资料不足、退回补正等分支。

**交付条件**：每个结论能指出依据和阻塞项，不能通过勾选任务直接伪造修复结果。本文未进行现行法规逐条核验；正式规则须另行完成来源核查与专业复核。

### 工作包 D：材料与导出闭环

**主要文件**：`src/services/docs.js`、`src/routes/sync.js`、`web/src/views/CaseDetail.vue`、`db/schema.sql`、文书版本及校验测试。

- [ ] 文书采用可识别的字段模型；LOCK 从案件事实渲染，GEN 单独编辑，避免依赖任意 HTML 的文本存在性判断。
- [ ] 校验返回“文书、字段、期望值、实际值、错误原因”，缺字段、错字段、冲突和过期校验都可区分。
- [ ] 服务端保存与导出统一校验；预览、定稿、PDF 以同一版本为准。
- [ ] 增加历史快照，支持恢复；处理用户输入与 AI HTML 的安全展示。
- [ ] 验证改企业名、删信用代码、改日期、先校验后改文书、直接调导出 API 等绕过路径。

**交付条件**：错误事实被阻断；正确文书能编辑、定稿、追溯、导出；页面不再对所有校验结果固定显示“校验通过”。

### 工作包 E：监测、异议与凭证可信闭环

**主要文件**：`src/services/checks.js`、`src/services/cert.js`、`src/routes/sync.js`、`web/src/views/CaseDetail.vue`、`web/src/views/Verify.vue`、`tools/gen_pdf.py`、凭证/异议相关迁移。

- [ ] 同步状态明确来源、采集时间、核验范围和模拟标记；比较官方与第三方状态，而非仅比较渠道自身前后状态。
- [ ] 异议函可下载，发送由企业自行办理并登记；回复和超期建议有明确记录。
- [ ] 先确定凭证声明：证明的是哪些数据、哪个时点、什么依据；未满足条件时不能签发肯定性修复凭证。
- [ ] 保存签发时快照，区分原始内容被改与来源后来合法更新；必要时将旧凭证标为需更新。
- [ ] 补签发幂等、并发控制、撤销、过期、篡改和链条验证；有效期、签发时间、证据范围进入完整性保护。
- [ ] 网页与下载凭证展示相同状态；PDF 加可访问的核验链接与二维码，并实际用手机核验。

**交付条件**：至少跑通一条“已修复→第三方未同步→异议登记→复核→凭证→扫码”的可解释案例；模拟步骤均明确标注。

### 工作包 F：交付验收与演示

**主要文件**：新增 app 部署文档/服务配置、`start.sh`、`start.bat`、`src/config.js`、`src/db.js`、`package.json`、需求文档和 README。

- [ ] 新增数据库迁移机制，演示种子由显式模式控制，正式环境不能因空表自动灌演示数据。
- [ ] 配置生产签名密钥、HTTPS 会话设置、登录频率限制、备份与恢复；去掉生产默认开发配置。
- [ ] 将现有四项隔离复核转为持久回归测试，补 API/数据库集成和一条浏览器主流程。
- [ ] 在全新环境按交付说明安装并验证：建库、启动、登录、办理、PDF、手机核验、重启恢复。
- [ ] 准备成功、条件不足、渠道未同步三种演示案例，以及 AI 不可用时的模板路径。
- [ ] 统一需求完成状态、接口清单、表数量、会话时长和凭证算法；形成一份可复核验收记录。

**交付条件**：交付包与当前 app 源码同版，项目成员能够独立启动；演示不依赖临场改数据库。

## 6. M2–M4 的建议调整

1. **M2：可试用的数据与运营基础**。先做授权导入/人工复核、独立数据源适配接口、快照与差异解释、失败重试和定时任务；再做已具备接入条件的真实数据源。完善用量记录与基础配额，支付另立里程碑。
2. **M3：机构效率与留存**。授权关系先在 M1.1 完成，此阶段增加授权企业的批量检查/导出、到期提醒、政策更新通知和运营指标；融资先做授权分享凭证入口，不能把可扫码等同银行已采信。
3. **M4：规模化与新终端**。基础租户隔离必须前置；更复杂租户管理、部署治理与小程序根据真实用户需求推进。

建议下一项实际编码任务就是 **工作包 A：注册角色限制和机构企业授权隔离**，随后紧接工作包 B。先让新用户能在正确权限内办理，再增加采集源、订阅收费与融资对接。
