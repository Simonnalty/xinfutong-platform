# 信复通平台 · 法学院协作需求清单

- 日期：2026-10-31
- 提出方：信复通技术组
- 用途：平台规则库与文书模板的法律依据核验，及平台自身合规文件起草
- **期望反馈时间：2026-11-04 前**（比赛演示节点 11-07，需预留联调时间）

---

## 一、背景（一句话）

信复通是一个辅助民营企业**自行办理**信用修复的工具平台：企业录入失信事实与证据 → 平台按规则诊断可申请时点与材料清单 → 生成文书草稿 → 企业自行向主管机关提交。平台**代企业准备材料，不代替行政机关作出决定，不代为送达**。

因此平台输出的一切结论都必须有明确的法规出处。目前的规则数据是开发阶段填的占位示例，**没有任何一条经过核验**，这是当前最大的缺口，需要法学院补齐。

---

## 二、需要提供的四类内容

| # | 类别 | 具体内容 | 优先级 |
|---|---|---|---|
| 1 | **修复规则表** | 选定案件类型的完整规则，含依据、等级、时点、前置条件 | P0 |
| 2 | **材料清单与官方表格** | 该类型申请修复需提交的全部材料、份数、盖章要求，以及官方制式表格原文 | P0 |
| 3 | **文书模板法律审校** | 平台自动生成的三类文书措辞审校 | P1 |

## 三、P0 之一：修复规则表（最关键）

### 3.1 需要选定一类案件

平台首版只支持**一种**失信情形做透，不做全类型。请法学院在下列两条路径中确定一条：

| 路径 | 适用情形 | 主管依据 | 与平台现状的匹配度 |
|---|---|---|---|
| **A. 行政处罚信息修复** | 一般失信行为的行政处罚信息 | 信用修复管理办法一类规章 | 平台现有字段（缴款日、整改情况、无新增同类）与之完全对应，**建议优先** |
| **B. 移出经营异常名录** | 未按期公示年报、地址失联等 | 经营异常名录管理一类规章 | 目前演示数据用的是这一类，但"移出"与"信用修复"是两套程序 |

**需要你们明确回答**：A 和 B 哪一条规则更清晰、更容易向企业解释、更适合作为首个演示案例？如果选 B，我们需要替换现有演示数据。

### 3.2 规则表填写模板

请按下表逐项填写（可另附文档）。**每一格都必须能指向一份可查的文件**，不能只写结论。

| 字段 | 填写要求 | 对应平台字段 |
|---|---|---|
| 情形名称 | 官方全称，不用口语简称 | `cases.event` |
| 适用依据 | 文件全称 + 发文机关 + 文号 + 具体条款 | `rule_versions.source` |
| 施行日期 / 是否现行有效 | 必须注明版本，若已修订请给最新版 | `rule_versions.effective_at` |
| 失信等级 | 轻微 / 一般 / 严重，以及**分级的判断标准** | `cases.level` |
| 最短公示期 | 多少个月/年，从何时起算 | `rule_params` |
| 可申请修复的时点 | 从哪个日期起算（处罚决定日？公示起始日？义务履行日？） | `rule.apply_from` |
| **前置条件 1：已履行义务** | 是否必须已缴纳罚款/完成整改？如何证明？ | `cases.obligation_at` |
| **前置条件 2：已纠正失信行为** | 整改的认定标准是什么？由谁认定？ | `cases.rectified` / `rectify_at` |
| **前置条件 3：无新增同类失信** | 观察期多长？范围是同类还是任何失信？ | `cases.no_new_similar` |
| 所需材料 | 逐项列出，见第四节 | `doc_templates` |
| 受理机关 | 具体是哪个部门（原处罚机关 / 信用平台 / 发改部门） | `cases.authority` |
| 法定办理时限 | 受理后多少个工作日办结 | `rule_params` |
| 常见驳回原因 | 你们知道的实务中被退回的主要原因 | 用于诊断提示 |

### 3.3 特别需要确认的三个问题

1. **"可申请日"到底怎么算**：是"最短公示期届满日"，还是"义务履行完毕 + 公示期满"两者中较晚者？
2. **三个前置条件是"且"还是"或"**：必须全部满足才能申请，还是满足其一即可？
3. **事实无法确认时怎么办**：平台目前的处理是显示"待核实"并阻止导出正式文书，这个保守做法在法律上是否恰当？

### 4.2 官方表格原文

- 平台生成的文书，**加盖企业公章后是否可以直接提交**？

- 平台生成的文本若与官方表格措辞有出入，是否构成提交无效？

这一条直接决定产品形态，请务必明确。

## 五、P1：文书模板审校

平台会生成三类文本，请审校措辞并指出法律风险：

| 文书 | 用途 | 需要你们确认 |
|---|---|---|
| 信用修复申请书 | 向主管机关申请 | 必备要素是否齐全、措辞是否得当 |
| 守信承诺书 | 承诺不再发生同类失信 | 承诺内容的法律效力边界 |
| 异议申诉函 | 官方已修复但第三方平台未同步时使用 | 收件对象、可主张的权利范围 |

**核心担心**：这些文本由系统自动生成，若措辞接近官方文书，是否会被认定为"仿制官方文书"或"伪造证明材料"？请给出明确的红线。

## 六、P1：平台合规文件

平台会处理两类受法律保护的信息：企业信息，以及法定代表人的姓名、手机号、身份证/银行流水扫描件（后者属敏感个人信息）。需要法学院起草或审校：

| 文件 | 说明 |
|---|---|
| 隐私政策 | 收集范围、用途、保存期限、删除方式、第三方共享情况 |
| 用户协议 | 服务性质（辅助工具非代理）、责任限制 |
| 企业数据授权书 | 企业盖章授权平台处理其材料，需明确授权范围与撤回方式 |
| 敏感个人信息单独同意书 | 上传身份证/银行流水类材料时单独勾选，不能与其他条款捆绑 |
| 免责声明 | 明确平台结论不构成法律意见、不保证修复结果、最终决定权在行政机关 |

---

## 七、需要书面确认的五个法律边界

这五条决定平台能不能对外说"可用"，请逐条给出结论：

1. **平台能否代企业生成申请文书**，还是只能提供空白模板和填写指导？
2. **平台出具的"修复状态说明/数字凭证"法律性质是什么**？会不会被认为在出具虚假证明？是否应改称"企业材料自述"？
3. **"信复通"这个名称**是否涉及需要前置审批的字样（如"信用""征信"）？
4. **是否需要备案为信用服务机构**？部分省份对信用服务有备案要求，湖南是否有？
5. **平台声称"辅助办理"是否构成无照经营的法律服务/代理服务**？
